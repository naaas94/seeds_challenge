**Plan:** seeds-match-api v1.0 | **Skill:** executor-subtask-execution

## §1. Task Statement

Build a Python FastAPI application exposing a conversational AI agent backed by an explicit ReAct loop and a Yahoo Finance tool, with per-conversation in-process memory and two HTTP endpoints (`POST /chat`, `GET /chat/{conversation_id}`). The application runs in Docker via a single-worker uvicorn process.

**Non-goals:** Persistence across restarts, authentication, rate limiting, streaming, multiple tool providers, multi-worker deployment, any LangChain `AgentExecutor` usage.

## §2. Shared Contracts (binding on all subtasks)

### Types / Interfaces (binding for this subtask — test targets)

| Symbol | Expected behavior tested |
|--------|--------------------------|
| `POST /chat` without conversation_id | Returns 200 with auto-generated UUID in `conversation_id` |
| `POST /chat` with existing conversation_id | Returns 200; second call receives prior context |
| `GET /chat/{id}` — known ID | Returns 200 with all message types: human, ai, tool |
| `GET /chat/{id}` — unknown ID | Returns 404 |
| `POST /chat` — LLM exception | Returns 500 with `{"error": "Agent execution failed", "detail": ...}` |
| `serialize_content` — list content | Returns joined text or `"[tool call — no text content]"` |
| `serialize_content` — str content | Returns str unchanged |
| `MAX_ITERATIONS` fallback | Returns fallback string when loop cap hit |
| `get_stock_info` — valid ticker (mocked) | Returns price block string |
| `get_stock_info` — invalid ticker (mocked, no regularMarketPrice) | Returns "No data found for..." string |
| `get_stock_info` — yfinance exception | Returns "Failed to retrieve data..." string |

|-----------|-----------|

**Inputs:** T6 complete — full `app/main.py` with both routes, lifespan, ROLE_MAP, serialize_content

**Outputs:** `tests/test_app.py`, `tests/conftest.py`

**Kill criteria:**
- HALT if any test makes live network calls to OpenAI or Yahoo Finance.
- HALT if the 500 error test does not assert `{"error": "Agent execution failed", "detail": ...}` shape.
- HALT if the 404 test asserts an empty message list instead of a 404 status code.
- HALT if the multi-turn test does not verify that the second request's mock LLM receives the prior message in its history (inspect mock call args).
- HALT if `ConversationStore` is shared across test functions without re-instantiation (asyncio.Lock event-loop isolation issue).

**Log tier:** `standard`

**Risks & mitigations:**
- Risk: mocking `ChatOpenAI` — the lifespan hook instantiates it; need to patch before app startup. Mitigation: use `TestClient` with `lifespan` overridden, OR patch `langchain_openai.ChatOpenAI` at import time, OR override `app.agent.loop.agent_loop` entirely for integration tests.
- Risk: `pytest-asyncio` requires `asyncio_mode = "auto"` in pytest.ini or `@pytest.mark.asyncio` per test. Mitigation: add `asyncio_mode = "auto"` to `pyproject.toml` or `pytest.ini`.
- Risk: The `store` in `app/main.py` is a module-level singleton — tests that hit the TestClient share state unless the store is reset between tests. Mitigation: monkeypatch `app.main.store` with a fresh `ConversationStore()` in conftest.

## Implementation Guide

### Mocking strategy

The simplest approach: patch `app.agent.loop.agent_loop` for integration tests (avoids mocking LLM internals), then write separate unit tests for `agent_loop` logic with a mocked LLM.

```python
# Integration test approach — patch the whole agent_loop
with patch("app.main.agent_loop", return_value="Mocked reply") as mock_loop:
    response = client.post("/chat", json={"message": "hello"})
```

For unit tests of `agent_loop` itself:

```python
# Unit test approach — patch get_llm_with_tools
from unittest.mock import MagicMock, patch, AsyncMock
from langchain_core.messages import AIMessage

mock_llm = MagicMock()
mock_llm.invoke.return_value = AIMessage(content="Apple is $195", tool_calls=[])
with patch("app.agent.loop.get_llm_with_tools", return_value=mock_llm):
    with patch("app.agent.loop.get_tool_map", return_value={}):
        ...
```

For `get_stock_info` unit tests:

```python
from unittest.mock import patch, MagicMock

def test_get_stock_info_valid_ticker():
    mock_info = {
        "regularMarketPrice": 195.23,
        "longName": "Apple Inc.",
        "currency": "USD",

        "trailingPE": 28.5,
        "fiftyTwoWeekHigh": 220.0,
        "fiftyTwoWeekLow": 164.0,
        "longBusinessSummary": "Apple Inc. designs, manufactures...",
    }
    with patch("yfinance.Ticker") as mock_ticker_class:
        mock_ticker_class.return_value.info = mock_info

    assert "Apple Inc." in result
```

    data = response.json()

    assert response.status_code == 200
    assert response.json()["conversation_id"] == cid

def test_chat_multi_turn_continuity(client):
    """Second request should receive prior context in LLM call args."""
    response1 = client.post("/chat", json={"message": "First message"})
    cid = response1.json()["conversation_id"]
    response2 = client.post("/chat", json={"message": "Follow-up", "conversation_id": cid})
    assert response2.status_code == 200
    # Verify the conversation has both messages stored
    history = client.get(f"/chat/{cid}").json()
    roles = [m["role"] for m in history["messages"]]
    assert roles.count("human") == 2

def test_chat_500_on_agent_exception(client, monkeypatch):
    import app.main as main_module
    async def raise_exc(*args, **kwargs):
        raise RuntimeError("LLM exploded")
    monkeypatch.setattr(main_module, "agent_loop", raise_exc)
    response = client.post("/chat", json={"message": "Crash me"})
    assert response.status_code == 500
    detail = response.json()["detail"]
    assert detail["error"] == "Agent execution failed"
    assert "LLM exploded" in detail["detail"]

@pytest.mark.asyncio
async def test_agent_loop_max_iterations_fallback():
    from unittest.mock import MagicMock, patch
    from langchain_core.messages import AIMessage
    from app.agent.loop import agent_loop, MAX_ITERATIONS
    from app.memory.store import ConversationStore

    # LLM always returns tool_calls → loop never terminates naturally
    mock_llm = MagicMock()
    mock_llm.invoke.return_value = AIMessage(
        content="",
        tool_calls=[{"name": "get_stock_info", "args": {"ticker": "AAPL"}, "id": "call_1"}],
    )
    mock_tool = MagicMock()
    mock_tool.invoke.return_value = "price data"

    store = ConversationStore()
    with patch("app.agent.loop.get_llm_with_tools", return_value=mock_llm):
        with patch("app.agent.loop.get_tool_map", return_value={"get_stock_info": mock_tool}):
            result = await agent_loop("test-id", "What is AAPL?", store)

    assert "unable to complete" in result.lower()
    assert mock_llm.invoke.call_count == MAX_ITERATIONS

## §5. Filtered Adversarial Items

### Load-bearing assumptions (affecting T8)

- `(llm_with_tools.invoke() is synchronous and returns a valid AIMessage with .tool_calls | §2 Types: agent_loop contract | If mocked incorrectly (returns a dict or str), loop logic breaks | T5, T8)` — Mock must return `AIMessage(content="...", tool_calls=[])` — an actual AIMessage object, not a dict.

- `(ROLE_MAP lookup uses type() identity | §2 Types: ROLE_MAP | If a LangChain subclass is returned, role is "unknown" | T6, T8)` — Test `test_get_history_returns_messages` asserts `"human"` and `"ai"` in roles — this would fail if ROLE_MAP lookup returns `"unknown"` for real message objects.

### Hidden couplings (affecting T8)

- **CONFIRMED** — `(POST /chat test must mock agent_loop at the right layer | §2 Tests: no live API calls | If mocking only yfinance but not LLM, agent_loop blocks on real OpenAI | T6, T8)` — Integration tests must patch `app.main.agent_loop` or patch `langchain_openai.ChatOpenAI` at import. The conftest approach patches ChatOpenAI before TestClient startup.

- **SUSPECTED** — `(ConversationStore._lock is an asyncio.Lock; if tests run in different event loop, lock panics | §2 Types: ConversationStore | T3, T8)` — Mitigation: `monkeypatch.setattr(main_module, "store", fresh)` in conftest creates a fresh store per test. The `@pytest.mark.asyncio` tests create their own store instances.
